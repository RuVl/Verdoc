## 1. Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/purchases/<customer_token>/` | оплаченные заказы покупателя, позиции, состояние токенов |
| `GET` | `/api/files/<allocation_token>/` | поток файла, без почты в URL |
| `POST` | `/api/purchases/<customer_token>/refresh/<allocation_id>/` | новый токен одной аллокации |
| `POST` | `/api/purchases/<customer_token>/refresh-all/` | новые токены всех аллокаций покупателя |

`GET /api/purchases/...` отдаёт по каждой позиции: название из снапшота, цену, и для каждой
аллокации — `id`, `is_downloadable` (токен жив), `download_url`, `expires_at`.

Просроченный `customer_token` → 404 с подсказкой запросить письмо заново, а не 403:
существование токена не должно подтверждаться.

Старый роут `/api/order/file/<email>/<uuid>/` остаётся ещё один релиз — по нему продолжают
приходить люди из писем, разосланных до R2.

## 2. Ротация и письмо

- `POST /api/send-links/` (форма «мои покупки» на сайте) — ротирует `Customer.access_token`,
  сбрасывает TTL, шлёт письмо. Это и есть механизм отзыва старых ссылок.
- Письмо после оплаты — **не** ротирует токены, иначе повторная покупка убивает ссылки,
  которыми покупатель поделился. Только шлёт текущую ссылку.
- Текст письма: одна ссылка, срок действия `PURCHASES_PAGE_TTL`, предупреждение, что ссылка
  открывает **все** покупки и делиться ею не стоит.
- `Allocation.token` при ротации кабинета не трогается.

## 3. Фронт

Роут `/purchases/:token`, компонент в стилистике сайта. Макеты в `design/` — десктоп и `_mob`,
по правилам из `CLAUDE.md`.

У каждого товара три кнопки:

- **скачать** — заблокирована, если токен истёк, с подсказкой про обновление ссылки;
- **скопировать ссылку** — покупатель вправе делиться и файлом, и ссылкой на него;
- **обновить ссылку** — выдаёт новый токен и разблокирует скачивание.

Отдельно кнопка «обновить все ссылки» над списком.

Правило одно и без спецкейсов: доступно то, у чего токен свежий. Отдельной логики
«недавняя покупка» не нужно — она следует из TTL.

Существующая страница `views/MyPurchases.vue` (форма ввода почты) остаётся: это точка входа,
когда ссылка потеряна.

## 4. Снять слой совместимости

R1 оставил в API предметные имена, чтобы не трогать фронт. Здесь они убираются вместе с
правкой фронта, одним коммитом на оба конца:

| Было (R1) | Станет |
|---|---|
| `passports` в `/api/countries/` | `products` |
| `quantity` у товара | `available` |
| `passport_id` в `POST /api/order/` | `product_id` |
| `user_email` в `POST /api/order/` | `email` |

Правится `frontend/src/models/Country.js`, `models/Passport.js`, `stores/order.js`.
Переименование JS-классов (`Passport` → `Product`) — по желанию, на витрине термин остаётся.

## 5. Проверка

Сценарий целиком: заказ → оплата → письмо с одной ссылкой → страница покупок → скачивание →
дождаться истечения токена файла (или сдвинуть `token_expires_at` руками) → кнопка заблокирована →
обновить ссылку → скачивание работает → форма «мои покупки» → новое письмо → **старая** ссылка
на кабинет отдаёт 404, ссылки на файлы продолжают работать.

Отдельно: ссылка из письма, разосланного до R2, всё ещё открывает файл.
