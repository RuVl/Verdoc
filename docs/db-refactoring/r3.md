## 1. Откуда взялось приложение рассылок

Ветки `feature/add-broadcasting` больше нет: она была удалена на GitHub, PR по ней не заводился.
Уцелел dangling-коммит `883990c` (2026-07-27, 26 файлов) — из него и восстановлено всё:
`Broadcast`, TinyMCE-редактор с тремя шаблонами админки (включая скрипт, переключающий редактор
в тёмную тему вслед за админкой), команда `broadcast`, страница отписки, строка в `cronjob`.
Коммит помечен тегом `recovered/add-broadcasting`, чтобы его не собрал сборщик мусора.

Тот коммит вместе с `django-tinymce==5.0.0` откатывал Django с 6.0.6 до 5.2.16. Откат не
перенесён и не понадобился: пакет объявляет `django>=4.2` без верхней границы, виджет
рендерится на 6.0.6.

## 2. Язык письма

Разобран в [ADR-0009](../adr/0009-email-follows-the-customers-language.md). Коротко: язык живёт
на `Customer`, потому что письмо о выдаче отправляет вебхук Plisio, где браузера покупателя нет.

Заодно `Customer` получил queryset. «Покупатель» был определён дважды по-разному — в
`customer/admin.py` по `paid_at__isnull=False`, а в первоначальном плане этого релиза по
`orders__status__in=PAID_STATUSES`. Оставлен `paid_at`: этот штамп ставится ровно один раз в
`Order.mark_paid()`. Общие методы — `buyers()`, `leads()`, `subscribed_buyers()`.

## 3. Отписка

`Unsubscribe` не перенесён — отписка это `Customer.is_subscribed` + `unsubscribed_at`. Ветка на
прод не попадала, переливать нечего.

Сама страница отписки переехала с Django-шаблона на роут SPA `/unsubscribe/:token` поверх
`POST /api/unsubscribe/<token>/`. Копия оказалась там же, где остальная копия сайта (vue-i18n),
язык приезжает в `?lang=` и подхватывается гвардом роутера. Главное же — прежняя версия
отписывала на **GET**, а сканеры ссылок Gmail и Outlook предзагружают все URL из письма: людей
отписывало бы без их участия.

## 4. BroadcastDelivery

Строка на пару `(broadcast, customer)` с `UNIQUE`. Команда работает в две фазы: сначала
`bulk_create(..., ignore_conflicts=True)` строк `PENDING` на всех получателей, затем проход по
`PENDING` и `FAILED` с закрытием каждой строки сразу после отправки. Отсюда три свойства:
повтор идёт только упавшим, крон, упавший посередине, при следующем запуске продолжает, а не
начинает заново, и на вопрос «получал ли этот покупатель рассылку X» есть ответ.

Счётчики `total_recipients` / `sent_count` / `failed_count` / `error_log` с `Broadcast` удалены и
стали аннотациями в админке. `error_log` заменён списком упавших доставок с адресом у каждой.

## 5. Двуязычная рассылка

`mailing/translation.py` регистрирует `subject` и `body` — тот же механизм, что уже держит
`Country.name` и `Product.name`. В админке это `subject_en` / `subject_ru` и `body_en` / `body_ru`,
каждое поле body со своим TinyMCE (`TranslationAdmin` копирует виджет, объявленный в форме под
непереведённым именем `body`). Отправка идёт под `translation.override(customer.language)`,
незаполненный язык падает на фолбэк modeltranslation.

Тестовая отправка шлёт по письму на каждый язык — вычитывать надо обе версии.

## 6. Проверка

Прогнано: 147 тестов (`make dev-test`), из них 28 в новом `mailing`.

Сквозной сценарий на dev-стеке:

- письмо выдачи приходит на языке `Customer`, а не текущей сессии;
- рассылка двум покупателям с разными языками — каждому свой `subject` и своё тело;
- прерванный прогон + повторный запуск: дублей нет, добит только упавший;
- отписка по ссылке из письма, повторное открытие той же ссылки не падает, следующий прогон
  этого адреса не берёт;
- `/admin/mailing/broadcast/add/` на Django 6.0.6: два редактора, тёмная тема админки
  переключает и их;
- главная показывает лоадер, ошибку с кнопкой повтора и «товаров пока нет» по отдельности.
